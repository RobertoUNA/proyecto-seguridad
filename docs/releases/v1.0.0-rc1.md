## 4. Resumen de Cambios, Excepciones y Limitaciones Conocidas (`Ítem 5.3`)

### 4.1 Novedades de la Versión
1. **Cruce Geoespacial (`FLOW-01`):** Endpoint `/api/cantones/:id/panorama` que calcula la relación entre delincuencia, accidentalidad e infraestructura de atención.
2. **Consultas Acotadas (`FLOW-02`):** Filtros dinámicos con cotas máximas para evitar denegación de servicio (`CTL-02`).
3. **Módulo de Logs Seguros (`CTL-06`):** Trazabilidad con `X-Correlation-Id` y hash SHA-256 (`actor_id`).

### 4.2 Excepciones de Seguridad Vigentes
Todas las excepciones temporales se encuentran registradas formalmente en [`docs/ssdcl/REGISTRO-HALLAZGOS.md`](../ssdcl/REGISTRO-HALLAZGOS.md) con fecha de vencimiento `2026-12-15`:
- **`EXC-01`**: Paquetes transitivos de `@nestjs/platform-express` v10 (mitigado por API de solo lectura `GET`).
- **`EXC-02`**: Paquetes de tiempo de construcción en `devDependencies` de NestJS CLI.
- **`EXC-03`**: 9 CVEs de severidad HIGH en paquetes base del runtime del backend (`multer`, `body-parser`, `lodash`), aprobada formalmente por Billy Ugalde y aplicada en [`.trivyignore.yaml`](../../.trivyignore.yaml).

### 4.3 Limitaciones Técnicas Conocidas
- **API Exclusiva de Solo Lectura:** La versión no procesa cargas multipart ni operaciones `POST`/`PUT`/`DELETE` públicas.
- **Granularidad Territorial:** Los datos se encuentran agregados a nivel cantonal, no distrital ni barrial.

## 5. Plan Documentado de Rollback y Recuperación (`Ítem 5.4`)

Ante cualquier degradación crítica, indisponibilidad o fallo tras el despliegue:

### 5.1 Versión Base de Recuperación Verificada
Se utiliza como versión objetivo el registro inmutable en [`deploy/last-approved-release.json`](../../deploy/last-approved-release.json):
* **Release de Retorno:** `v1.0.0-rc0-baseline` (Commit `4844d2a`)
* **Compatibilidad de Base de Datos:** `requires_db_down_migration: false` (Las migraciones SQL `001..004` son estrictamente aditivas e idempotentes mediante `CREATE TABLE IF NOT EXISTS`).

### 5.2 Procedimiento de Reversión

**En Windows (PowerShell):**
```powershell
powershell -ExecutionPolicy Bypass -File scripts/rollback.ps1
```

**En Linux / macOS:**
```bash
bash scripts/rollback.sh
```

### 5.3 Comprobaciones Posteriores al Rollback (Smoke Tests)
Tras revertir los contenedores, se ejecuta la verificación de salud de la API:

**En Windows:**
```powershell
powershell -ExecutionPolicy Bypass -File scripts/smoke-test.ps1 -BaseUrl "http://localhost:3000"
```
*(El reporte se genera automáticamente en `reports/smoke-test-<sha>-<timestamp>.json`, comprobando los endpoints `/api/health`, `/api/cantones` y `/api/delitos/tipos`).*
