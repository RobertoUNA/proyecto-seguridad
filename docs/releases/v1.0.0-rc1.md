## 3. Resumen de Cambios y Limitaciones Conocidas (`Ítem 5.3`)

### 3.1 Novedades de la Versión
1. **Cruce Territorial Dinámico (`FLOW-01`):** Endpoint `/api/cantones/:id/panorama` con cálculo del `indice_cobertura` (0 a 100) y ratio proporcional ponderado con infraestructura de salud y seguridad.
2. **Capas OSINT Filtradas (`FLOW-02`):** Consulta acotada de delitos (OIJ) y accidentes viales (COSEVI) con límites estrictos de resultados para prevenir DoS (`CTL-02`).
3. **Módulo de Logging Seguro (`CTL-06`):** Trazabilidad con `X-Correlation-Id` y ofuscación de IPs con hash SHA-256 (`actor_id`).

### 3.2 Limitaciones Técnicas y Excepciones Vigentes
- **Exclusividad de Solo Lectura:** La API expone únicamente operaciones HTTP `GET`. No se permite subida de archivos ni mutación externa de datos.
- **Excepciones de Dependencias:** Se mantienen vigentes las excepciones temporales **`EXC-01`** y **`EXC-02`** en dependencias transitivas de NestJS v10 hasta el `2026-12-15`, mitigadas por el diseño de solo lectura de la API.
- **Granularidad Cantonal:** Los datos del índice se calculan a nivel de cantón (84 cantones de Costa Rica), no a nivel de distrito individual.

## 4. Plan Documentado de Rollback y Recuperación (`Ítem 5.4`)

En caso de detectarse una anomalía funcional, degradación de rendimiento o alerta crítica de seguridad en producción posterior al despliegue:

### 4.1 Versión Base de Recuperación Verificada
Se utiliza como versión objetivo el registro previo inmutable en [`deploy/last-approved-release.json`](../../deploy/last-approved-release.json):
* **Release de Retorno:** `v1.0.0-rc0-baseline` (Commit `4844d2a`)
* **Compatibilidad de Base de Datos:** `requires_db_down_migration: false` (Las migraciones SQL son estrictamente aditivas e idempotentes mediante `CREATE TABLE IF NOT EXISTS`).

### 4.2 Procedimiento Operativo de Reversión

#### En Entornos Windows (PowerShell):
```powershell
# Ejecutar rollback inmediato hacia la versión aprobada previa
powershell -ExecutionPolicy Bypass -File scripts/rollback.ps1
```

#### En Entornos Linux / macOS / Docker Host:
```bash
# Ejecutar reversión automatizada
bash scripts/rollback.sh
```

### 4.3 Verificación Posterior al Rollback (Smoke Tests)
Tras completar la reversión del contenedor, se debe verificar inmediatamente la salud de los endpoints principales:
```powershell
powershell -ExecutionPolicy Bypass -File scripts/smoke-test.ps1 -BaseUrl "http://localhost:3000"
```
El script comprobará `/api/health`, `/api/cantones` y `/api/cantones/1001/panorama`, generando el reporte de confirmación en `reports/smoke-test-post-rollback.json`.
